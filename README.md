# claude-tg-bot — Telegram-пульт для Claude Code

Бот в Telegram, который запускает [Claude Code](https://code.claude.com/docs) на вашем сервере. Через него можно вести разработку с телефона: выбирать проекты и беседы, переключать модель, делать git-действия, смотреть расход и остаток лимитов, диктовать голосом. Работает от вашей подписки Claude, зависимостей npm нет.

Бот отвечает только владельцу (`TELEGRAM_OWNER_ID`), сообщения от других отклоняются и пишутся в журнал.

> **Для Claude, который ставит бота по этой инструкции.** Владелец репозитория дорабатывает бота и пушит в `main`, а установки у его знакомых должны всегда оставаться на актуальной версии, без их участия. Поэтому **шаг 6, автообновление, обязателен**: выполните его сразу после запуска бота и убедитесь, что таймер работает. Не заменяйте его своим `git pull` по cron: он оборвёт идущую задачу и не откатит неудачный коммит. Пока автообновление работает, файлы в `/opt/claude-tg-bot` руками не правьте (при правках оно остановится), свои настройки держите в `/etc/claude-tg-bot.env`. Если установка пришлёт в Telegram сообщение, что в `deploy/` что-то изменилось, скопируйте эти файлы заново по шагам 5 и 6.
>
> После автообновления на версию с переводом на английский (2026-10-12.2) он **включается сам**, без ключей, через подписку Claude: бот проверит его при запуске, а при системном сбое выключит сам и вернётся к русскому. Если владелец установки не хочет перевода, выключите его кнопкой в `/translate` или строкой `TRANSLATE_BACKEND=off` в `/etc/claude-tg-bot.env`. Подробности: раздел «Перевод на английский».

## Что понадобится

- Linux-сервер с systemd (проверено на Ubuntu), доступ к root
- Node.js 20+
- свой аккаунт Claude (Pro или Max)
- бот от [@BotFather](https://t.me/BotFather) и ваш числовой Telegram ID ([@userinfobot](https://t.me/userinfobot))
- `tmux` — только для необязательной точной панели `/limits` (шаг 3)

Имя пользователя `claudebot` и путь `/opt/claude-tg-bot` зашиты в юнит и в подсказки бота, поэтому оставьте их как в инструкции.

## Установка

Все команды выполняются от root (`sudo -i`).

**1. Claude Code и пользователь.** Claude Code под root не позволяет отключать подтверждения, поэтому бот работает от отдельного пользователя.

```bash
npm install -g @anthropic-ai/claude-code
apt install -y git tmux

useradd -m -s /bin/bash claudebot
install -d -o claudebot -g claudebot /opt/projects
install -d -o claudebot -g claudebot -m 750 /var/lib/claude-tg-bot
```

**2. Код.**

```bash
git clone https://github.com/kikysar/claude-tg-bot.git /opt/claude-tg-bot
```

**3. Токен Claude.** Войдите в свой аккаунт и получите долгоживущий токен:

```bash
sudo -iu claudebot claude setup-token
```

Команда выведет ссылку для входа и в конце токен. Это значение `CLAUDE_CODE_OAUTH_TOKEN`.

`/limits` работает и так: пятичасовой и недельный лимиты бот берёт из ответов Claude Code, цифры появляются после первого же ответа и обновляются с каждым следующим. Чтобы видеть ещё и аккаунт и читать точную панель `/usage`, войдите вторым способом, обычным (необязательно):

```bash
sudo -iu claudebot claude auth login
```

**4. Настройки.**

```bash
cp /opt/claude-tg-bot/.env.example /etc/claude-tg-bot.env
chmod 600 /etc/claude-tg-bot.env
nano /etc/claude-tg-bot.env     # TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_ID, CLAUDE_CODE_OAUTH_TOKEN
```

**5. Запуск.**

```bash
cp /opt/claude-tg-bot/deploy/claude-tg-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now claude-tg-bot
journalctl -u claude-tg-bot -f
```

Откройте бота в Telegram и отправьте `/start`.

**6. Автообновление бота (обязательно).** Раз в 10 минут root-таймер сверяется с репозиторием и, если владелец запушил новое, подтягивает его сам:

- бот перезапускается, только если изменился `bot.js` или `gemini.js`, и только когда он не занят: задача не идёт и последние три минуты ему никто не писал. Иначе обновление ждёт следующего раза;
- перед заменой проверяется синтаксис `bot.js` и `gemini.js`, а после перезапуска, что бот не падает. Если что-то не так, скрипт возвращает прежнюю версию, эту больше не пробует и пишет владельцу установки в Telegram;
- об успешном обновлении бот сам сообщит в чате («Бот обновлён»).

```bash
cd /opt/claude-tg-bot/deploy
install -m 755 claude-tg-bot-update /usr/local/sbin/
install -m 644 claude-tg-bot-update.service claude-tg-bot-update.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now claude-tg-bot-update.timer
systemctl start claude-tg-bot-update.service     # проверка вручную
journalctl -u claude-tg-bot-update -n 5 --no-pager -o cat
```

В журнале должно появиться «Обновлений нет: …», а `systemctl list-timers claude-tg-bot-update.timer` покажет следующий запуск.

Каталог `/opt/claude-tg-bot` должен быть клоном репозитория (шаг 2) и принадлежать root. Сам скрипт и юниты ставятся копированием, как у ночного обновления Claude Code, и репозиторием не подменяются: запись в репозиторий не должна давать запуск нового кода от root. Если в обновлении изменилось что-то в `deploy/`, скрипт напишет об этом владельцу установки в Telegram, и тогда эти файлы нужно скопировать заново: повторите команды выше.

## Автообновление Claude Code (необязательно)

Сам `claudebot` обновить глобальный npm-пакет не может, поэтому обновляет root по ночному таймеру. Вместе с CLI приходят новые модели, бот заметит их сам и напишет в чат.

```bash
cd /opt/claude-tg-bot/deploy
install -m 755 claude-code-update /usr/local/sbin/
install -m 644 claude-code-update.service claude-code-update.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now claude-code-update.timer
```

## Голосовой ввод (необязательно)

Распознавание локальное: whisper.cpp и статический ffmpeg, без root и без API-ключей. Без них бот просто отвечает, что голос не настроен.

```bash
apt install -y build-essential cmake curl xz-utils

sudo -iu claudebot bash -c '
set -e
D=/var/lib/claude-tg-bot/stt
mkdir -p $D/bin && cd $D
curl -L https://johnvansickle.com/ffmpeg/releases/ffmpeg-release-amd64-static.tar.xz \
  | tar -xJ --strip-components=1 -C bin --wildcards "*/ffmpeg"
git clone --depth 1 https://github.com/ggml-org/whisper.cpp
cd whisper.cpp
cmake -B build && cmake --build build -j --config Release
bash models/download-ggml-model.sh small-q5_1
bash models/download-ggml-model.sh base
'
```

Для ARM-сервера замените `amd64` на `arm64` в ссылке на ffmpeg. Язык по умолчанию русский, меняется через `WHISPER_LANG` в `/etc/claude-tg-bot.env`. После изменения настроек выполните `systemctl restart claude-tg-bot`.

## Перевод на английский (включён по умолчанию)

Кириллица обходится Claude заметно дороже английского: по замеру на беседах этого бота около 0,85 токена на русский символ против 0,26 на английский, а выхлоп к тому же стоит впятеро дороже ввода. Поэтому бот переводит ваше сообщение на английский перед отправкой Claude, а ответ Claude переводит обратно на русский.

**По умолчанию переводит Haiku через тот же Claude Code и ту же подписку.** Ключи, доплаты и настройка не нужны: перевод включается сам при установке и при обновлении бота. Каждый перевод идёт отдельным коротким процессом `claude -p` на модели Haiku 5.5: без инструментов, без файлов настроек, без размышлений и без кэша промпта (тексты каждый раз новые, а запись в кэш стоит вдвое дороже обычного ввода). Текст передаётся не «голым», а JSON-объектом `{"text": "…"}`, чтобы модель видела в нём материал для перевода, а не обращённую к ней просьбу. На вызов уходит около 700–950 токенов в зависимости от версии Claude Code (почти всё — обвязка самого Claude Code), по прайсу это порядка $0,0001, то есть доли процента лимита подписки. Деньги с карты не списываются: если Claude Code вдруг вошёл по ключу API, а не по подписке, вызов обрывается.

При каждом запуске бот прогоняет пробный перевод и пишет результат в журнал (`journalctl -u claude-tg-bot | grep "Проверка переводчика"`). Если Claude Code переводчика не пускает (вход по подписке не принят, нет модели Haiku, изменились параметры вызова, вход оказался по ключу), **перевод выключается сам**, бот пишет об этом одно сообщение и работает по-русски, как до перевода. Ничего не теряется: задача, которая шла, дорабатывается по-русски. Когда причина устранена: `/translate` → «Включить» (бот сначала проверит связь). Исчерпанный лимит подписки поломкой не считается: переводчик просто ждёт десять минут, пока Claude и сам не отвечает. Нехватка памяти тоже не поломка: при меньше 260 МБ свободной памяти (`TRANSLATE_MIN_MEM_MB`) перевод на этот раз пропускается, а процессы переводчика идут строго по одному, и при нехватке памяти ядро убивает их первыми, а не беседу.

Дальше в боте `/translate` показывает состояние и расход переводчика, а «🧪 Проверить» прогоняет образец в обе стороны. Включение и выключение перезапускает процесс Claude, поэтому первое сообщение после него один раз перепишет кэш беседы.

Что остаётся на сервере: блоки кода, код в обратных кавычках, ссылки, абсолютные пути, имена файлов и строки, похожие на ключи, переводчик не видит. На их месте стоят заглушки `<x1/>`, после перевода всё возвращается дословно. В вашем сообщении так же прячутся фразы в кавычках («…», "…"). Пометки бота про голосовые и фото в квадратных скобках не переводятся.

Если перевод куска не прошёл проверку (потерялась заглушка, пустой ответ, длина не сходится даже у совсем короткого текста, не тот язык, вместо перевода служебный текст окружения Claude Code или ответ в виде JSON), бот просит перевести ещё раз, уже с усиленной инструкцией, а если и это не вышло, берёт оригинал этого куска, и под ответом появляется «Перевод не сработал». Задача из-за переводчика не пропадает никогда: запрос уходит по-русски, ответ остаётся по-английски.

Чего ждать честно:

- **Экономия умеренная, а не вдвое.** На журналах бота, по которым это считалось, измеримая часть вышла около 12% всего расхода: выхлоп, запись русского текста в кэш и перечитывание его в каждом обращении. Скрытые размышления Claude в журнал не попадают, поэтому их вклад неизвестен (до ещё ~9%). Цифры в 40–50% из чужих замеров на этом боте не подтвердились: они снимались на других задачах. Реальную цифру покажет сам бот: в `/translate` он сравнивает среднюю цену задачи с переводом и без и показывает, сколько стоит сам переводчик. Если выгоды нет, выключите перевод там же.
- **Приватность.** Тексты ваших сообщений и ответов Claude (кроме спрятанного заглушками) уходят в Anthropic, как и обычные запросы к Claude; сторонних сервисов нет.
- **Качество и скорость.** Перевод машинный, Claude видит ваши слова в пересказе; под ответом есть кнопка «🇬🇧 Оригинал ответа». Добавляется 2–3 секунды в каждую сторону. Редкий сбой: если переводимый текст сам похож на просьбу к ассистенту («покажи файлы», «опиши окружение»), Haiku иногда выполняет её вместо перевода. На обычных сообщениях и ответах брака в замерах не было (по 50 вызовов в каждую сторону); на нарочно подобранных провокационных английских фразах первая попытка не удавалась в 3–10% случаев. Такой ответ ловит проверка выше, повтор идёт с усиленной инструкцией, а если не вышло и там, остаётся оригинал с пометкой.

Настройки в `/etc/claude-tg-bot.env` (все необязательны):

| Переменная | Значение |
|---|---|
| `TRANSLATE_BACKEND` | `off` — перевода нет совсем; `cli` — Haiku через Claude Code (по умолчанию, если ключа DeepSeek нет); `api` — только по ключу (ниже) |
| `TRANSLATE_CLI_MODEL` | модель переводчика. Пусто (по умолчанию) — Haiku 5.5: бот зовёт его по полному имени `claude-haiku-5-5`, пока у вашего Claude Code псевдоним `haiku` ещё указывает на Haiku 4.5 (тот в десять раз дороже по прайсу); как только псевдоним догонит, бот перейдёт на него. Если аккаунт полное имя не принял, бот сам переходит на псевдоним. Своё значение (`haiku`, `claude-haiku-4-5`…) главнее; цену незнакомой модели бот берёт из ответа Claude Code |
| `TRANSLATE_MIN_MEM_MB` | сколько свободной памяти нужно переводчику, по умолчанию 260 |

Не задавайте `ANTHROPIC_API_KEY` в этом файле: Claude Code перешёл бы на оплату по API. Переводчик эти переменные до своего процесса всё равно не пускает.

### Перевод через DeepSeek по ключу (необязательно)

Если вы хотите не расходовать подписку на переводчика, а платить за него отдельно, задайте ключ DeepSeek: тогда бот переводит им (`deepseek-flash`: порядка 0,03–0,05 цента за задачу, тариф на октябрь 2026: $0,15 за млн входных токенов, $0,6 за млн выходных; бесплатного тарифа у DeepSeek нет, баланс нужно пополнить). Но тогда тексты уходят третьему лицу, DeepSeek, а не только в Anthropic.

```bash
# ключ: platform.deepseek.com → API keys
echo 'DEEPSEEK_API_KEY=sk-…' >> /etc/claude-tg-bot.env
systemctl restart claude-tg-bot
```

С ключом перевод идёт через DeepSeek, пока не задан `TRANSLATE_BACKEND=cli`. Если DeepSeek недоступен, задача всё равно выполняется: запрос уходит по-русски, ответ остаётся по-английски. После трёх сбоев подряд переводчик отдыхает две минуты. Об отказе по ключу или по деньгам (401, 402) бот напишет сам, не чаще раза в шесть часов. Ключ процессам Claude Code не передаётся.

Другая модель или сервис: `TRANSLATE_MODEL`, `TRANSLATE_API_URL` и `TRANSLATE_API_KEY` в том же файле настроек (ключ `TRANSLATE_API_KEY` главнее `DEEPSEEK_API_KEY`). Подойдёт любой OpenAI-совместимый `/chat/completions`, в том числе с бесплатным тарифом, если его лимитов хватает; условия таких тарифов (в том числе использование ваших текстов самим сервисом) смотрите сами. Расход в `/translate` при этом считается по тарифу `deepseek-flash`, то есть для другого сервиса это условная цифра.

## Модели Google — Gemini через Vertex AI (необязательно)

Когда лимит подписки Claude кончился, а работа не закончена, в `/model` можно выбрать Gemini и продолжить **ту же беседу**: он видит всю историю, читает и правит файлы и запускает команды теми же инструментами Claude Code, а когда вы вернётесь на Claude, тот увидит всё, что сделал Gemini. Переключаться можно сколько угодно раз.

**Как это устроено.** Агентом остаётся тот же Claude Code: те же инструменты, тот же файл беседы, тот же `--resume`. Меняется только адрес, куда он шлёт запросы «к модели»: вместо Anthropic это маленький мост внутри бота (`gemini.js`; слушает только `127.0.0.1` на случайном порту и требует секрет, который знает лишь бот). Мост переводит запросы Anthropic Messages в Vertex AI `streamGenerateContent` и обратно: историю, инструменты, картинки, потоковый ответ и коды ошибок. Вход по подписке и ключи Anthropic в этот процесс не передаются; у Claude всё остаётся как было.

**Что нужно.** Проект Google Cloud с включённым Vertex AI API и сервисный аккаунт с ролью «Vertex AI User»; его ключ (JSON) создаётся в Google Cloud Console → IAM → Service accounts → Keys. Положите ключ вне репозитория:

```bash
install -m 640 -o root -g claudebot ключ.json /etc/claude-tg-bot-gemini.json
echo 'GEMINI_KEY_FILE=/etc/claude-tg-bot-gemini.json' >> /etc/claude-tg-bot.env
systemctl restart claude-tg-bot
```

При запуске бот отправляет Google один короткий настоящий запрос. Ответили: бот один раз пишет «Модели Google подключены». Не ответили: бот пишет причину дословно (чаще всего Vertex AI API не включён или у аккаунта нет роли), а Claude работает как раньше. В `/model` рядом с моделями Claude появляются модели Gemini и кнопка «🧪 Проверить связь с Google» (две пробы стоят доли цента); после исправления причины перезапускать бота не нужно.

| Модель | Вход / выход, $ за млн токенов |
|---|---|
| Gemini 3.1 Pro (самая сильная) | 2 / 12; запрос длиннее 200 тыс. токенов вдвое дороже |
| Gemini 3.7 Flash | 0,75 / 3,75 |
| Gemini 3.5 Flash, Gemini 3 Flash, Gemini 3.1 Flash-Lite | ≈0,75 / 3,75, ≈0,5 / 3, ≈0,25 / 1,5: прайс оценён по соседним моделям, в меню такие цены со знаком ≈ |

**Деньги.** Gemini оплачивает Google Cloud, а не подписка Claude, и лимиты подписки он не тратит. Мост считает расход по прайсу: `/limits` и `/status` показывают расход за сегодня, за всё время и по моделям, а в конце каждого ответа бот пишет цену задачи. Если задача зациклится, остановит суточный потолок `GEMINI_DAILY_USD` (по умолчанию $25): мост перестаёт пускать к Google, а бот объясняет, как поднять потолок или вернуться на Claude. Учёт лежит рядом с состоянием бота, в `gemini/spend.json`.

**Чем работа с Gemini отличается.**

- Перевод на английский не нужен и не применяется: Gemini получает русский как написано. Кэш не греется (у Google он живёт считанные минуты, и пинги дороже, чем перезапись), а беседу сжимает сам Claude Code, когда контекст дорастёт до 200 тыс. токенов (`GEMINI_COMPACT_WINDOW`; запросы длиннее 200 тыс. у Pro вдвое дороже).
- Усилие в `/model` для Gemini: `low`, `medium`, `high`. Обычное усилие уже `high`, а `xhigh` и `max` для Google то же самое (бот это пишет); сколько именно размышлять, Gemini решает сам.
- `WebSearch` с Gemini недоступен: это серверный инструмент Anthropic. Страницы Gemini читает через `WebFetch`, искать может командой `curl`.
- Размышления Gemini в беседу не попадают. Нужные Vertex подписи вызовов инструментов мост хранит на диске (`gemini/signatures.jsonl`), а для вызовов, сделанных Claude, подставляет пустую подпись, которую Vertex принимает.
- После возврата на Claude его кэш остыл: первое сообщение один раз перепишет беседу в кэш.
- Gemini 3.1 Pro пока в статусе preview и изредка отдаёт повреждённый вызов инструмента: мост повторяет запрос до двух раз, потом сообщает об ошибке. Насколько Gemini хорош как агент в обвязке Claude Code, зависит от задачи, поэтому судите по своим.

**Проверено** на настоящем Claude Code 2.1.308 и настоящем Vertex AI: цепочка Claude → Gemini → сжатие → Claude → Gemini в одной беседе (Anthropic принимает файл беседы, дописанный через мост, и наоборот), чтение и правка файлов, `/compact` через мост, `WebFetch`, передача усилия.

**Claude Code на компьютере.** Мост можно запустить и отдельно: `node gemini.js --key ключ.json --port 8788` печатает `ANTHROPIC_BASE_URL` и `ANTHROPIC_AUTH_TOKEN`. С этими переменными, `ENABLE_TOOL_SEARCH=false` и `--model gemini-3.1-pro-preview[1m]` Claude Code работает через Google на любой машине.

Настройки в `/etc/claude-tg-bot.env`:

| Переменная | Значение |
|---|---|
| `GEMINI_KEY_FILE` (или `GOOGLE_APPLICATION_CREDENTIALS`) | путь к ключу сервисного аккаунта. Без него моделей Google нет, и бот работает как раньше |
| `GEMINI_DAILY_USD` | суточный потолок расхода, $; по умолчанию 25, `0` — без потолка |
| `GEMINI_LOCATION` | регион Vertex AI, по умолчанию `global` |
| `GEMINI_MODELS` | свой список моделей через запятую вместо пяти по умолчанию |
| `GEMINI_LEVEL` | уровень размышлений для обращений, где Claude Code сам его не задаёт; по умолчанию `medium` |
| `GEMINI_COMPACT_WINDOW` | с какого размера контекста Claude Code сжимает беседу с Gemini, по умолчанию 200000 |

Пока выбрана модель Gemini, тексты задач, содержимое прочитанных файлов и выводы команд уходят в Google Cloud. Ключ читает `claudebot`, то есть и агент на сервере: давайте сервисному аккаунту только роль «Vertex AI User».

## Команды бота

`/project` выбрать проект · `/newproject` создать · `/status` состояние · `/model` модель (Claude или Gemini), усилие и режим · `/limits` остаток лимитов · `/sessions` беседы проекта · `/compact` сжать беседу · `/git` git-действия · `/new` начать заново · `/stop` остановить задачу · `/warm` прогрев кэша · `/translate` перевод на английский · `/help` помощь.

Если файл беседы проекта пропал с сервера (его удалили или перенесли), Claude Code её продолжить не может и отвечает «No conversation found with session ID». Бот сам забывает этот номер, начинает новую беседу, говорит об этом одной строкой и отправляет то же сообщение заново: ничего делать не нужно, а прежний запрос не теряется.

## Проверка перед выкладкой

`node test/harness.js` запускает бота на макетах: Telegram, Claude Code, ffmpeg и whisper подменены, время ускорено в 2000 раз, так что шесть часов прогрева проходят за секунды. Ни сети, ни расхода лимита подписки, зависимости не нужны. Прогон занимает около минуты и заканчивается строкой «Итог: N ✓, 0 ✗». `VERBOSE=1` добавляет журнал бота, `SHOW=1` печатает экраны лимитов. Отдельные короткие прогоны про запуск: `BOOTCASE=имя node test/harness.js`; для Gemini это `gemini` (весь путь: ключ, меню, переключение туда и обратно, расход и потолок, усилие), `gemini-again`, `gemini-nokey` и `gemini-down`.

`node test/gemini-test.js` проверяет мост на поддельном Vertex: перевод запросов и ответов, подписи, ошибки, учёт денег.

`bash test/updater-test.sh` проверяет скрипт автообновления: настоящий git в соседней папке, а `systemctl`, `journalctl` и `curl` подменены, так что службу и сеть тест не трогает. Прогон занимает секунды.

## Безопасность

- В рабочем режиме Claude Code запускается с `--permission-mode bypassPermissions`: он выполняет команды и правит файлы без подтверждений, от имени `claudebot`. Не давайте этому пользователю sudo и держите в `PROJECTS_ROOT` только то, что можно ему доверить.
- Токены лежат только в `/etc/claude-tg-bot.env` (права 600, читает systemd). В репозиторий они не попадают, `.gitignore` это страхует. Ключ DeepSeek (если он есть) лежит там же и до процессов Claude Code не доходит. `ANTHROPIC_API_KEY` в этот файл не кладите: Claude Code перешёл бы с подписки на оплату по API.
- Перевод включён по умолчанию: текст ваших сообщений и ответов Claude (без кода, путей, ссылок, ключей и цитат в кавычках) уходит в Anthropic, как и обычные запросы к Claude. Только если вы сами задали ключ DeepSeek, он уходит в DeepSeek. Выключается в `/translate` или строкой `TRANSLATE_BACKEND=off`.
- Модели Google (если подключены): ключ сервисного аккаунта лежит вне репозитория, в журнал и в беседу не попадает. Мост слушает только `127.0.0.1` и требует секрет. Пока выбран Gemini, содержимое задач и прочитанных файлов уходит в Google Cloud.
- Кто получит `TELEGRAM_BOT_TOKEN`, сможет писать от имени бота, но выполнять задачи сможет только `TELEGRAM_OWNER_ID`. Если токен утёк, перевыпустите его в @BotFather.
